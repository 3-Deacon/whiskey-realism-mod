**Identity (spec component 2):** a belief is keyed by `UnitKey` (`name:commander`, the sidecar convention), never by `InstanceId`, which is in-session only. `Update` matches a detection to a belief by `UnitKey`; when no belief has the key and a remembered belief has the same unit name (the part before `:`) and `UnitTyp`, that belief is re-keyed (its commander changed, e.g. after an appointment) instead of a second belief being created. So a save/load, which changes every instance id, and a commander change never count one army twice. **Collisions:** `name:commander` is assumed unique per live group but not trusted: when two live detections in one review carry the same `UnitKey`, neither is merged into the other; each keeps its own belief keyed `UnitKey#InstanceId` for the session (persisted under that composite key, rebound by the same rule after a load) and `OnceLog.Warning("campaign-planner:unitkey-collision", …)` logs it once. **Renames:** vanilla renames groups (`UpdateUnitNameDefault` sets the GameObject name after a combination, 17159), so a renamed army arrives under a new key with a new name and the re-key rule cannot match it; instead, a remembered belief that was not matched this review and has the same `UnitTyp` is retired (not re-keyed, not merged) when a new-key detection lies inside its uncertainty radius, and the detection becomes a fresh belief. A rename therefore leaves no ghost, and two armies that are both seen are never merged.

**Detection rule (exact; spec component 2):** for each enemy campaign group `e` (alliance at war with the side, active, visibility state ≠ 0, not a fleet), visible when:

## G8 — Garrison manning beyond the capital (after G7)

Why: vanilla defends only the capital. `AssignUnitToDefendCapital` (11668-11869) is the only proactive defense; `CheckOccupationOfLostCities` (job 29, 17392-17485) is reactive — it sends the closest available unit to retake a lost own-state town that no enemy currently holds, if zone supply allows. No `AICampaign` code creates or mans garrisons (no `isgarrison: true` / `garrisonreference =` write in 8775-17933): garrisons exist only from the scenario (81991-81993) and as the dummy a finished fort spawns (`CreateGarrisonDummy` 82081-82093, `basicgarrisonsize[level]`; 96676-96686); `SeparateUnits` keeps every garrison out of `ownunits` (10510-10513), and the capital need's garrison loop is dead (11742-11750). Key towns, rail hubs, ports, depots and forts away from the capital are therefore held only by whatever happens to stand there.
