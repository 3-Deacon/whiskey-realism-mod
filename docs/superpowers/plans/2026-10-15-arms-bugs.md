## Decisions on record

- **Fix scope.** The user said "Fix all" for every item.
- **Transpiler.** On 2026-10-15 the user approved one Transpiler: "Approve (Recommended)" for the autoresolve 6-pounder fix (item 1). It is the only new Transpiler in this slice.
- **No other blocking patch.** There is no skipping Prefix. The other new patches are Postfix, or Prefix-snapshot with a Finalizer or Postfix restore:
  - the W&L budget-purchase gate makes vanilla's own gate refuse by swapping the cost pref for the call;
  - the purchase fix masks research lists for the call.
- **AI purchase fix.** The coordinator's G9 request preferred a Prefix on `PlaceWeaponOrder` that swaps an unorderable id for vanilla's next candidate. That cannot see vanilla's candidates (they are locals of `CheckPurchaseWeapons`), and it would have to skip when none remains. So the mask on `CheckPurchaseWeapons` was chosen. It changes nothing but the candidate set and never skips. The rule helper `Strategic/WeaponOrderability.cs` is named for G9's reuse.
- **Same-model merges.** These never downgrade the target, even when statsguns rounding makes the gain exceed what the source returned; stock clamps at 0.
- **Recorded, not fixed.**
  - Identical import-relations branches (`BUG-AI-019`): a fix needs a Transpiler, and the Union's intended expression is not certain.
  - Weapon -1 index faults (`BUG-AI-020`): not reachable on shipped data. This includes the init-pass misalignment, which cannot trigger before career start selection.
- **#14.** It does reach W&L career creation, and its forced weapon automanage only sets the starting value. The player's in-game weapon-panel checkbox stays the choice. The only change is mirroring vanilla's `currentoperation > 0` return, so #14 can never re-force the flag in a running game.
- **Out of scope (stage G).** AI re-arming priority, and replacing vanilla's random weapon-purchase pick.

### Item 6 as built (stage E delta)

- **Need per lane.** Industry is the larger lane need, guns (artillery units) or the other units. Each lane's need is the larger of:
  - the coverage gap, `1 − equippable / (aiminnumberofequippableunits × units)`, where `ArmsCoverage.Fill` replicates vanilla's count at 16287-16312;
  - the quality gap, `1 − own average WSF / best orderable WSF`.
- **Signals.** `WeaponDeficit = IndustryGap = Industry`. `ArtilleryDeficit` is the gun lane (was always 0).
- **Import projects.** `ProjectDoctrineSignals.ArmsImportViability = 1 + (influenceofblockadesonweaponimports − 1) × own blockade` (vanilla 64120-64124). It is 1 before the first review, and non-finite values read as 1. ArmsImport scores (projects 0-4) are multiplied by it.
- **Removed.** `NeedSnapshot.WeaponStock`, `NeedSnapshot.TroopsInRecruitment` and `CampaignNeedRuntime.Sum`.

## Tuning watches (behaviour accepted by design; watch the `policy-plan` rows before tuning)

- **Uniformly best-armed lane.** Once a lane is armed throughout with the best model the alliance can order and nothing better is in stock, its coverage gap reads 1 for as long as that lasts. Industry then pushes Industrialization and project 102. This is what vanilla's own purchase trigger sees.
- **Early 1861.** While the scenario's starting stock covers 15 % of units, Industry can read near 0 despite Mixed Muskets, because no better rifle is orderable yet. The quality gap is 0 with nothing orderable.
- **#14 guard.** The setup-screen guard covers every realism checkbox write, not only weapons. It is expected to be a no-op in a running game: `MainMenu` lives under `UICampaign`, which `MainMenuControls.Activate(false)` deactivates. Static code cannot prove it. If an in-game automanage box (finances, weapons) used to snap back on and now stays off, the guard took effect. Whether in-game locking was wanted is then a separate decision for the user.
