# Patch Catalog

Canonical numbered list of the Harmony patches in `src/WhiskeyRealism/Patches/`. One row per patch file; a file holding several patch classes lists them all in its row. Unless the row says otherwise, the file is `Patches/<first class>.cs`.

Decompile lines refer to `/tmp/gt_src/asm/Assembly-CSharp.decompiled.cs` (Steam build 14703111). Gate column gives the exact config key from `Plugin.cs` (all default ON except `Force All Succession Events`). "master only" means no flag besides `Enabled` (section General); `Enabled = false` at startup skips `PatchAll`, so no patch is applied at all. Battle writers additionally need `Tactical Commander Mode = Active` (checked by `Tactical/TacticalWriteGuard`); `MonitorOnly` and `Off` make every battle write a no-op.

## Conventions

- **Ordinals are never reused.** Removed patches keep their number in [Removed patches](#removed-patches). New patches take the next free number (next: **#100**; #80 is BC9's `SkirmisherScreenDistancePatch`, #81-#91 the campaign logistics fixes from `fix/campaign-logistics-bugs`, #92-#99 the W&L economy fixes).
- **One concern per file** under `src/WhiskeyRealism/Patches/`. Helpers without `[HarmonyPatch]` (`AICampaignReflect`, `TacticalPatchIds`, `LogisticsSwaps`) get no row.
- **Every** `Prefix` / `Postfix` / `Finalizer` body is wrapped in `TelemetryPerf.Scope("<campaign|tactical>.patch.<name>", ...)`.
- **Battle writes** (movement, stance, formation, facing, combat behavior) go through the battle core's order executor (`Tactical/Battle/OrderExecutorRuntime`): the arbiter's producers (#68) and the inline paths of #42 and #56 (`OrderExecutorRuntime.TryPlanInline` / `ExecutePlannedInline`). Every write passes `TacticalWriteGuard` (Commander Mode Active, AI-controlled unit, W&L player-owned units and exposed player-owned descendants protected, feuding units refused except #42's own feud replay, fail closed). The only other battle writers are #59's rollback, #60's deployment `SetGroupFormation`, #42's no-snapshot fallback and #44's `macroai`. `SkirmisherScreenDistancePatch` writes nothing: it is a result override of vanilla's own `GetUnitLinkData` input (no vanilla writer call), gated by `TacticalWriteGuard.CanWrite`. `ai_stance` is written only by `Util/TacticalStanceWriter` (the executor's Stance channel; carve-outs/yield rules in `Tactical/TacticalStanceOwnership.cs`). The battle-level `AIBattle.macroai` is written only by #44.
- **Patches never throw**: reflection is wrapped in try/catch and logged once (`OnceLog`); guards that swallow vanilla exceptions do so only when no Whiskey Realism frame is on the stack.
- **Source of truth:** shipped code > this catalog > per-patch design doc > archived spec/plan.
- **UI patches** #10-#14 touch menu methods that move between game builds; rollback for all five is `Override Vanilla Settings = false`.
